# 房间跳转与玩法测试

编辑器开始运行游戏，或启动 Development 构建后，先点击游戏视口，再按 **Ctrl + F10** 打开开发者面板。Esc 或再次按 Ctrl + F10 关闭。正在操作电脑、卡牌、音量设置等界面时，先退出该界面再打开。

## 当前地图内跳转

面板从当前主流程实际配置读取区域列表。MainGame 和 FullJourney 均可使用，包括矿区、办公室、回声／卡牌联合房间和博物馆；点击对应按钮会传送到该区域配置的入口，并激活该区域原有玩法。

- 可以跳转尚未解锁的区域；本次会话解锁进度会推进到该区域，但不会直接完成房间任务或打开完成门。
- 保留背包、养成和房间当前进度，不重置已挖地形。
- 自动解除开局镐子与喷气背包的教学锁，保留回声等房间自身的工具限制。
- 跳转清除移动惯性并恢复游戏输入。入口碰撞无法找到可用位置时，保留面板并显示错误。
- 已完成撤离的办公室不再强行进入，请选择独立办公室重新测试。

## 独立玩法测试

下半部分提供 MainGame、办公室、回声→卡牌→电视逃生、独立卡牌房、镜像博物馆、新涌现结尾、旧 FullJourney 的切图入口。独立卡牌房可以直接测试牌局，无需先完成回声通道。

切图会离开当前地图并重新建立目标房间，当前房间的运行进度不会保留。背包等 GameInstance 状态仍遵循原游戏逻辑；此入口不承诺清空所有养成数据。测试后可再次按 Ctrl + F10，选择“主游戏 · MainGame”返回重新载入的主流程。

原有 F4 菜单保持原规则。开发者入口、区域跳转及独立测试操作在 Shipping 构建中禁用；Development 打包中未包含的地图按钮置灰。

## 验证

自动化测试入口：`BrainMining.RoomDebug`。覆盖独立关卡资源、MainGame 全区域跳转、未解锁区域、装备教学锁、房间激活、背包保留、非法目标、Esc 关闭、输入恢复，以及主游戏→独立牌局→主游戏切图。

关闭 UE 编辑器后执行 `Scripts/Run_RoomDebugChecks.ps1 -Build`，使用项目现有的资源保护流程串行编译并运行无渲染测试。加 `-Render` 可运行带渲染版本。结果保存到 `Saved/Automation/RoomDebug/index.json`，日志在 `Saved/Logs/RoomDebug.log`。

2026-10-16 验证：UE 5.8 编辑器编译通过，3 项自动化测试全部通过（无渲染）。实际覆盖 MainGame 六个区域、Ctrl + F10 和 Esc、主游戏→独立卡牌房→主游戏往返。溶洞入口需要向上调整约 31 厘米以避开现有碰撞，调试跳转会在入口上方小范围寻找可用落点；地图资产和原入口配置不变。本轮未执行带渲染画面验收，也未构建 Shipping 包。
