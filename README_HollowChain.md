# 多房间、多空心矿区串联

本阶段扩展空心矿区的编辑、生成和单向推进，不替换旧版整面连接关卡，也不包含随机主路／随机支路生成。

## 打开示例

- 关卡：`/Game/MiningPrototype/Maps/Lvl_MiningHollowChain_Demo`
- 4 个主房间、3 个独立矿区、9 个可挖堵块、3 个侧洞室（其中 1 个隐藏入口）。
- 每区初始 24 个三轴分块；仍然最多 **30000 三角形／分块、128 分块／矿区**。
- 房间、矿区和洞室都保留为独立编辑对象；生成结果不是需要手工修改的源数据。

## 最少操作流程

1. 打开 **Tools → 矿业策划台**，选择生成器，进入“场景与空间”。
2. 摆放／复制 `MiningLayoutRoom`，修改“主房间连接顺序”，只标记一个起始房间。
3. 启用“使用空心矿区方案”，点击 **补齐相邻房间矿区**。它只创建缺少的矿区，不重置已有路径或洞室。
4. 选择对应 `REGION`，修改通道半径、矿区宽度、上下岩层厚度、堵块；点击“编辑路径点”调整中间形状。
5. 选择 `CAVE`，修改所属矿区、位置、尺寸、连接位置或隐藏入口。侧洞室不触发主房间推进。
6. “检查并重新生成”，确认状态为 Ready，然后保存当前关卡。

移动一个中间主房间，会更新前后两段的洞口端点，但保留中间手绘控制点。若因此坡度或净空不合法，会保留整张地图最后一次成功的网格、碰撞和小地图快照，并报告错误；调整控制点或撤销即可。

## 引用与兼容

- 新字段 `HollowRegions` 是串联矿区列表。按各矿区 `FromRoom / ToRoom` 对应的相邻主房间配对，不按列表位置生成。
- 列表非空时优先使用列表；列表为空时回退到旧 `HollowRegion`，旧的两房一矿区无需迁移。
- 空引用、重复配对、跨关卡引用、跳接／反接和缺少连接都会拒绝生成。删除或重排房间后，请先修正现有矿区归属；“补齐”不会擅自删除或改接旧矿区。
- 参数预设不会复制矿区对象列表或房间身份。新增矿区操作支持撤销／重做。
- 关闭空心矿区方案后，原有整面连接／手绘形状方案保持原逻辑；已有形状编辑不能被空心模式静默覆盖。

## 运行时

- 每个矿区对应一个挖掘段；其普通岩石、堵块、支路和洞室全部属于同一段。
- 整个角色胶囊进入下一主房间并停留到确认时间后，上一段冻结，下一段激活。
- 示例启用 `SealAndRecycle`：更早矿区在玩家安全离开、入口位于视野后方一段时间后，先加不可挖封口，再释放运行中的网格和碰撞；至少保留最近上一段。
- 最后一个主房间不再激活新段。`R` 恢复整张地图、回收段、碰撞、堵块和推进状态。
- 回收不等于流式加载：重置所需初始网格仍保留在内存里。地图总段数增加仍会增加初始生成、存档和内存成本，不承诺任意扩大地图都维持相同帧率。
- 开发者小地图标记每段归属和玩家位置；不是实时挖掘表面扫描。

## 当前边界

- 2–16 个主房间，沿 +X 依次推进，相同或更低地板高度；当前不支持倒折或上坡主路。
- 每段相邻房间之间净距 1000–24000 cm；每条主路径 2–12 个点。
- 同一区通道采用固定半径 150–1000 cm，使用原有 16 边圆截面；各区半径可以不同。
- 外层基岩不得与其他矿区外壳或无关房间重叠。支路／洞室仍需位于各自矿区范围内。
- 新增矿区使用默认半径与宽度；房间太小或横向错开过大时，需要调整参数后再生成。
- 本阶段不包含种子随机、变半径、随机数量／长度支路、自动按 D1／D2 安排堵块、手工关卡预制内容或局部重随机。
- 本次不更新已打包的 Windows 可执行版本。

## 验证入口

- `Scripts/setup_hollow_chain.py`：仅在示例不存在时创建，拒绝覆盖已有示例。
- `Scripts/show_hollow_chain.py`：打开示例、选择生成器并显示矿业策划台。
- `Scripts/verify_hollow_chain.py`：加载保存后的示例，检查几何、碰撞、分组、错误编辑的原子性和预算。
- `Scripts/verify_hollow_chain_editor.py`：编辑器自动重建、共享房间端点、撤销／重做、新增矿区；不保存测试修改。
- `Scripts/run_hollow_chain_runtime.py`：实际移动挖穿三段、进入各侧洞室，再以定点测试验证推进边界、冻结、回收和重置。
- 原生测试：`BrainMining.HollowChain`。报告输出到 `Saved/Validation`。
