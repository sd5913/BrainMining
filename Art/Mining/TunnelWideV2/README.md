# 加宽通路 V2

本版单独保存，旧版通路和堵塞层文件仍在原目录。完整要求见 `optimized_prompt_zh.md`。

## 交付文件

- `SM_DescendingTunnel_Wide_Lowpoly.fbx`：仅含一个封闭的通路填充实体，45878 三角形。用作生成器切割体，不是洞壁网格。
- `Tunnel_Wide_Blockers_20.fbx`：仅含 20 个独立堵塞层，合计 19840 三角形，不包含参考通路。
- `Tunnel_Wide_V2.blend`：可编辑源文件，场景 `Descending_Tunnel_Wide_V2` 为通路，场景 `Tunnel_Wide_Blockers_V2` 为堵塞层及线框参考通路。
- `Tunnel_Wide_V2_Workspace.blend`：当前 Blender 工作窗口另存版本，包含旧版场景以便比较。
- `Tunnel_Wide_Front.png`、`Tunnel_Wide_Perspective.png`、`Tunnel_Wide_Blockers_Placement.png`、`Tunnel_Wide_Blocker_Detail.png`：正视图、立体视图、堵塞层分布及细节。

## 尺寸和造型

坐标和建模单位为米，FBX 使用单位元数据换算到 UE 厘米。两份 FBX 使用同一原点和轴向，所有对象变换保持位置 0、旋转 0、缩放 1。堵塞层顶点已经使用通路的共同坐标，导入 UE 时不要分别居中或对每个堵塞层重设原点。若整体移动、旋转或缩放通路，堵塞层必须使用相同变换。

以 Blender 正视图（相机在 −Y、X 向右、Z 向上）为准，主路从左上起点 `(-135,-28,65)` 到右下终点 `(135,55,-109)`。主路中心线长约 530.36 米，持续下降 174 米，有 7 条下降支路。为容纳宽段并保持支路互不贯通，调整了路线间距和端部延伸段。

旧版主路名义直径约 5.1 米。新版主路设计横向宽度 5.40～19.17 米，按弧长采样平均 11.27 米（约旧版 2.2 倍）；截面高度与横向宽度比在 0.8～1.16 之间连续变化，几何表面另带低多边形岩石起伏。宽度值为设计截面参数，最终体素并集与岩石表面会产生小幅偏差。

模型整体约 278.00 × 173.13 × 182.37 米。若 UE 要容纳全部通路，需重新设置岩层尺寸和切割体位置；可采用 2400～3000 cm 分块边长以控制分块数。入口和出口须穿过基岩外壳，不能把通路两端都完整包在外壳内部。

堵塞层分布：主路 10 个，其余 10 个分布在 7 条支路。沿通路方向的名义厚度 4.91～6.69 米，平均 5.84 米；旧版为约 2.1～3.4 米。侧面由新版通路与岩石板块做精确布尔交集得到，完整封住截面，两端保留不规则平面岩石表面。

## 验证

- `tunnel_validation.json`：通路单一连通体、欧拉示性数 2、正体积，零边界边、零非流形边、零重复面、零检测到的自交；所有中心线严格下降。
- `blockers_validation.json`：20 个堵塞层逐一通过封闭性和自交检查，截面 120 个方向射线验证，最大贴合误差约 0.000001 米。辅助封堵测试将通路分成 21 个连通区域，确认 20 个完整封堵。辅助测试使用放大 2% 的副本避免共面布尔误差，交付模型保持原始精确贴合。
- `export_verification.json`：两个 FBX 分别重新导入，网格数量为 1 和 20，均封闭；世界坐标包围盒误差不超过约 0.000016 米。

生成脚本：先用 Blender 自带 Python 执行 `plan_wide.py`，再依次以后台 Blender 执行 `build_wide.py`、加载产生的 blend 执行 `build_blockers.py` 和 `export_preview.py`。堵塞层脚本复用原版已验证的精确交集与检查方法。
