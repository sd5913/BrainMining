# 矿镐：三阶段立体破碎

养成数值现由“工具 → 矿镐养成数值”统一配置，使用说明见 [PickaxeBalanceEditor.md](PickaxeBalanceEditor.md)。正式默认等级 0～3 为三击、等级 4 为两击；下文的 23% / 56% 等比例记录旧实现与旧测试基线，新配置以养成工具为准。

根据三张深岩银河参考图，矿镐对同一处岩壁进行三次连续的真实地形切割。第一、二击也会改变岩体网格和碰撞，不再叠加黑色裂纹。第三击完成这一处的挖掘。

## 三击表现

1. 第一击切出较浅的不规则凹坑，出现大小不同的岩石切面和少量碎屑。
2. 第二击沿同一轮廓扩大、加深凹坑，残留岩面继续挡住该处，碎屑范围增加。
3. 第三击完成既定深度和范围的切割，清除该处残留岩体，并产生完整的破碎反馈。厚岩层后方仍然有新岩体，需要重新敲三下。

最终洞口大致为正方形，但四边、角部、内壁和底部都有不规则变化。每个位置只生成一次随机种子；三击共享相同的凹凸分布，不会每次重新随机。不同位置的破碎轮廓不同。

第一、二击分别使用最终宽度的 82% / 94%，中心深度的 23% / 56%；最后一击达到完整范围。深度沿各个切面变化，这些比例不等于移除体积比例。对射线检测到的薄岩壁，会限制前两击的最大深度，避免直接提前打穿；不规则岩层边缘仍可能剥落。范围、下移量、深度和速度升级继续参与计算。

## 进度和输入

- 轻微偏移准星可继续同一处。匹配以原始落点的横向距离和整个预定挖掘深度为依据，因此瞄准逐渐后退、倾斜的岩面不会重新从第一击开始。
- 不同位置分别保存进度；返回旧位置可继续，最多保留 64 处记录。
- 每次在实际落镐时重新射线判定距离和目标，随后提交对应阶段。第三击后新露出的岩体重新计数。
- 分块地形每一阶段均使用原有后台提交路径。提交期间不重复排队；失败时回退该次进度，可以重试。
- 外部挖掘或爆炸移除了已记录的受损表面时，清理相应进度。重置同时恢复岩体和计数。
- 松开鼠标保留已经开始的挥镐；界面阻挡、剧情阻挡、切换工具和重置取消尚未落下的那一击。
- 正式关卡控制器的左键松开回调使用 `EndMiningInput`，只停止连续挥镐；`CancelMining` 用于真正中断动作。关卡接管输入、关闭默认输入映射时，获准开始的挥镐仍可正常落下。
- `SuccessfulCuts` 每次实际切割增加一次；完整三击通常增加三次。`TargetPickaxeHits` 是局部阶段，`bLastPickaxeBreak` 表示第三阶段请求被接受，后台提交是否完成需检查实际地形状态。

钻头继续连续切割，炸弹继续不规则爆破。因为前两击现在也有真实缺损，矿物暴露与碰撞检测会随实际岩面更新。

## 实现与验证入口

- `MiningPickaxe.cpp`：三阶段请求、局部匹配、薄墙深度限制与提交后的进度维护。
- `MiningPickaxeGeometry.cpp`：有固定随机种子的方形轮廓、多层切面和封闭切割体。
- `ADiggableRock::MinePickaxe` / `AGeneratedMiningRock::MinePickaxe`：普通岩体及正式关卡的切割路径。
- `BrainMining.Pickaxe`：真实几何变化、薄墙前三击、局部进度、换工具、重置、随机轮廓、跨块切割和深度升级测试。
- `Scripts/verify_pickaxe_runtime.py`：MiningLab 中真实角色的挥镐时序、三阶段切割、碎屑、取消、重置和钻头检查，并记录前三击画面。启动参数 `-PickaxeThinWall` 切换到薄墙场景。
- `Scripts/verify_pickaxe_campaign.py`：FullJourney 第一矿区中的真实角色三击与分块提交检查，使用 NullRHI；支持独立游戏模式 `-game`，减少编辑器与游戏同时驻留的内存开销。

验证报告分别写入 `Saved/Automation/Pickaxe/index.json`、`Saved/Validation/Pickaxe/runtime.json` 和 `Saved/Validation/Pickaxe/campaign.json`。截图位于 `Saved/Validation/Pickaxe/strike-1.png` 至 `strike-3.png`，薄墙报告及截图位于同目录的 `ThinWall` 子目录。两个验证脚本都只修改临时运行世界，不保存地图。
