# 房间整面直连与单向分段挖掘（2026-10-05）

新增的独立空心矿区试验地图是 `Lvl_MiningHollow_Demo`，编辑方式见 `README_HollowRegion.md`。以下原有整面实心矿道功能保持不变。

地图：`/Game/MiningPrototype/Maps/Lvl_MiningDescent_AutoRooms`

现在是**房间整面直连**，不是自动绕路版。房间是编辑输入，矿道和周围不可破坏的基岩自动生成；矿道内部初始是实心可挖岩石，不是预先挖空的走廊。

每两个相邻房间之间的矿道仍是**独立的推进段**，但内部会自动拆成多个可挖块。现在 **30,000 面限制作用于每个内部块**，不再由整条长矿道共享；没有提高这个限制。进入下一房间后，上一段的所有块一起冻结，房间顺序和单向推进规则不变。

## 手动调整整条矿道形状

独立示例：`/Game/MiningPrototype/Maps/Lvl_MiningShapes_Demo`。示例从现有 Spaces 地图另存，第二条矿道带三个蓝色截面框；原 AutoRooms、Spaces 地图没有被覆盖。功能也可在原关卡使用，不必迁移地图。

1. 在大纲视图的 `AutoMine/Main/Links_AUTO` 中选择需要调整的 `LINK_...`。
2. Details → `Tunnel Shape` → **Add Shape Section**。系统在最大空档中央放一个截面框并选中它，初始形状保持原矿道。
3. 按 **W** 移动框，改变走向/高低；修改 **Width / Height** 调整宽高，单位厘米。框的坐标是截面中心，不是地板：增高时上下同时扩张。也可按 **R** 使用正值非均匀缩放；连接轴方向的缩放不改变截面尺寸。
4. 点击框上的 **Add Another Section** 增加控制点，或用 Alt 拖动复制后移开；控制点按连接轴的位置排序，无须手工填顺序。**Select Tunnel** 返回所属 LINK。
5. 默认拖动结束约 0.3 秒后生成；基岩、可挖岩石、支洞连接和小地图一起更新。关闭生成器 `Auto Rebuild` 时，可批量编辑，再点截面框的 **Rebuild Tunnel**。

如果 Details 里标准组件参数太多，在搜索框输入 `Tunnel` 即可只显示塑形参数和按钮；需要手填位置时清空筛选查看 Transform。竖井使用水平截面，Width / Height 对应 X / Y 尺寸。

删除/禁用截面框后，剩下的框重新连接。LINK 的 **Restore Straight Tunnel** 会禁用所有框，恢复整面直连但保留编辑数据；重新勾选框的 Enabled 即可恢复塑形。支持编辑器撤销/重做。框保存在 `TunnelShapes_EDIT` 文件夹，Play 中隐藏且无碰撞。也提供 `BP_MiningTunnelShapeSection` 供手工放置，但优先用 LINK 按钮，以免漏选 Tunnel。

**边界与安全：**两端始终自动贴满房间连接面，移动/改尺寸的房间会重新连接到中间框；中间框保持世界坐标不随房间偷偷移动。本版按相邻矩形截面线性连接，支持左右弯折、起伏、变宽变窄，不是自动寻路，也不是自由旋转的样条管。截面保持与两端连接面平行，不能旋转、沿连接轴倒退或绕回；每框须在两端之间，沿连接轴间隔至少 100 cm。每条矿道最多 24 个启用框，世界宽高 250–10000 cm。更细的弯曲可多加截面，陡坡/窄路仍须用角色实际测试。

无效尺寸、折回、跨主房间/其他矿道组、网格运算失败均不覆盖上一版有效地形、碰撞、分块或小地图。查看生成器 `Last Build Status`；调整房间顺序导致已编辑矿道不再连接相邻房间时，先禁用或重新分配它的控制框。无自动绕行。支洞会选择实际折线附近的接入位置；原来依靠重叠连接的空间若不再接触矿道，会报错，需移动空间或改 Straight Branch。

小地图按每个实际截面段记录轮廓，凹进去的弯道不会被一个大凸包填满。截面框不会增加主房间或推进组。每个内部块仍为 30,000 三角面预算，继续使用现有自动分块与简化；更多/更大的几何可能增加块数与重建开销，不保证帧率完全不变。修改关卡生成的是初始地形，不保留上一次 PIE 的挖掘痕迹；运行时不重新生成控制框几何。

验证入口：`BrainMining.TunnelShape` 原生测试、`Scripts/verify_tunnel_shapes.py` 几何/碰撞/失败回退检查、`Scripts/run_tunnel_shape_runtime_validation.py` 实际行走挖掘测试。`Scripts/setup_tunnel_shapes.py` 只在示例不存在时安装，不覆盖已有示例编辑。旧的打包目录不会自动更新。

本次验证：Editor / Development / Shipping 编译通过；原生塑形与小地图共 5 组测试、塑形几何 303 项、空间回归 378 项通过。保存重开保留三个截面与 16 个地图区域；实际角色移动和 TryMine 完成 171 次挖掘，到达全部后续房间，未瞬移、未关闭碰撞、未运行时重建。界面点击新增截面、自动重建、撤销和重做也已检查。结果只代表这些测试布局，不保证任意陡坡/任意塑形都可行走。

## 在矿道内编辑空间

主房间继续决定整面直连和单向推进。新增 `MiningLayoutSpace` 是洞穴/扩宽区的编辑标记，不是进度房间，也不是性能分块。

**最快开始：**选生成器，展开 `Spaces`，点击 **Add Mining Space**。可先用 `New Space From Room` 选择起始房间；不选则放在第一条矿道中间。新标记会自动选中，移动它、修改 `Space Size` 即可。也可以从 `/Game/MiningPrototype/Blueprints/BP_MiningLayoutSpace` 拖入，设置 `From Room` 或点击 **Assign Nearest Tunnel**。归属不会随着拖动偷偷切换。

独立示例地图 `/Game/MiningPrototype/Maps/Lvl_MiningSpaces_Demo` 提供可挖扩宽区、隐藏方形洞穴、开放椭球洞穴。原来的 AutoRooms 地图和房间布局没有被示例覆盖。

| 参数 | 含义 |
| --- | --- |
| Enabled | 暂时关闭空间；重建后恢复该处原地形，保留标记与手工内容 |
| From Room | 所属矿道的起始主房间；与它的下一个主房间连接 |
| Space Size | 长宽高，厘米；坐标在地板中心，改高度不挪地板 |
| Shape | Box 方形、Ellipsoid 椭球；首版不支持旋转，支持正值缩放 |
| Contents | Empty 预挖空；Diggable Rock 填充可挖岩石 |
| Connection | Overlap 与矿道/同段已连通空间重叠；Straight Branch 自动生成短直线支道，无绕行 |
| Entrance | 支道可选 Open 挖空、Rock Filled 保留整段岩石、Hidden Wall 只在洞穴前保留入口岩壁 |
| Entrance Rock Thickness | 隐藏入口沿支道中心线的岩壁厚度；曲面洞穴洞口其他位置厚度会不同 |
| Align Branch Floors | 默认开启，支道竖直截面连接到矿道/空间底部附近；关闭则以空间中心连线，适合特殊洞口 |
| Branch Width / Height | 支道独立宽高，不改变主矿道整面直连 |

隐藏入口要求 **Empty + Straight Branch + Hidden Wall**，洞穴本体必须与主矿道分开。入口保留的是可挖岩石，而不是基岩。地形生成同时扩张基岩外壳、清理旧隔墙，再应用现有分块与简化；预算仍为每块 30,000 面。空间不承诺绝对可行走：陡坡、竖井、椭球底部曲面仍需按实际角色测试。

编辑预览：蓝色为空腔，橙色为可挖区，灰色为禁用，粉色框是隐藏入口岩壁。显示的是编辑辅助范围，Play 中隐藏且无碰撞；剖面预览继续切实际生成地形。拖动时只更新标记，结束后约 0.3 秒重建。也可关闭生成器 `Auto Rebuild`，批量修改后点 `Rebuild Layout / Rebuild Tunnels`。

空间可复制、删除和撤销。同段重叠时空腔优先，不会被另一个实心空间回填。跨段空间、碰到主房间的空间、未连通空间和无效尺寸会拒绝应用，旧网格和碰撞保持不变；看生成器 `Last Build Status` 和标记 `Space Status`，红框不是成功生成的地形。首版上限为每布局 64 个启用空间，单轴世界尺寸 250–10000 cm，支道长度 100–10000 cm；这是防误操作范围，不是性能保证。

`ContentRoot` 是手工灯光、矿物、事件等内容的挂点：挂到该组件的物件跟随移动，但不会因 `Space Size` 或空间 Actor 缩放被拉伸。复制含内容的组合时请同时选中内容；重建不会删除或重建它们。Enabled 只控制地形，不自动隐藏内容；禁用/删除空间前应自行处理其手工内容。未实现矿物生成、敌人刷新、雾气事件绑定或内容随分段回收，这些可在此挂点上继续扩展。

验证脚本：`verify_mining_spaces.py` 检查几何、隐藏墙跨块挖穿/重置、无效编辑回滚、内容保留与原布局恢复；`setup_mining_spaces.py` 创建独立素材/示例，重复运行不覆盖已存在的示例编辑。

## 日常搭建只改房间

1. 在 Outliner 的 `AutoMine/Main/Rooms` 里选择 `ROOM_...`。
2. 拖动房间，或者修改 Details → `Room Size`。尺寸单位是厘米。
3. 等约 0.3 秒，矿道、基岩和起点自动更新；不需要挪通道盒子或样条点。
4. 用 `Connection Order` 决定顺序；编号不能重复。指定起点用 `Set As Start Room`。
5. 加房间时复制一个房间，改成未使用的编号；删除房间后，剩下的房间重新连接。复制起点后，要重新指定唯一的起点。

房间坐标是**地板中心**；增减高度不会把地板一起抬高。支持正值非等比缩放，但更推荐用 Room Size。当前支持轴对齐长方体房间，不支持旋转房间。

## 连接规则

- 按起点、后续 Connection Order 连接相邻房间，不按距离偷偷重排。
- 连接口占满选中的整个房间面：左右连接用完整的宽与高，上下连接用完整的地板/顶板。
- 两个房间面大小不同时，四角直线对应，形成线性收放的通道；不再限制成统一宽度的小门。
- 有水平间距时优先选择 X/Y 方向上间隔较大的相对墙面；只有没有水平分离、但有竖直间距时才自动选上下表面。
- 没有中间折点、不搜索绕行、不自动限制坡度，也不替你移动房间。
- 如需指定连接面，选择 `AutoMine/Main/Links_AUTO` 的 `LINK_...`，设置 `Start Wall / End Wall`。支持 Auto、±X、±Y、±Z，手动指定必须是一对朝向彼此的平行相对面。
- 直连模式不要编辑样条控制点；两端随房间自动更新，中间点不会用于生成。

基岩向通道外侧增厚，通道内尺寸不因基岩加厚而缩小。相邻房间内保持空心，可挖岩石端面精确停在房间面上，避免反复布尔裁切产生细碎薄片。

## 常用调节位置

选择生成器 `AUTO_TUNNELS_RoomFaces_Bedrock_Visibility`：

| 分类 / 参数 | 用途 |
| --- | --- |
| Generation → Auto Rebuild | 自动更新；关闭后用 Rebuild Tunnels 手动重建 |

| Play Visibility → Headlamp Intensity | 视线方向灯亮度，默认 4，范围 0–20 |
| Play Visibility → Fill Light Intensity | 玩家周围柔和补光，默认 1，范围 0–10 |
| Progression → Chunk Triangle Budget | 每个内部块的独立面数上限，默认及最大 30,000；修改后自动重建 |
| Mining Performance → Automatic Chunks | 自动拆分矿道内部，不改房间、连接面或基岩，默认开启 |
| Mining Performance → Chunk Length | 沿矿道最长坐标轴的最大分块跨度，默认 1200 cm；允许 400–3000 cm |
| Mining Performance → Simplify Chunks | 保守简化挖掘网格，默认开启 |
| Mining Performance → Simplification Tolerance | 每次简化的几何误差检查阈值，默认 0.5 cm，允许 0.05–1 cm |
| Progression → Room Entry Inset | 整个角色胶囊越过入室端面后额外深入的距离，默认 40 cm；小房间自动限制距离 |
| Progression → Room Entry Hold Time | 完整进入房间后持续确认时间，默认 0.15 秒 |
| Progression → Completed Segment Policy | 默认 Keep Frozen；可选 Seal And Recycle |
| Progression → Frozen Segments To Keep | 开启回收时，保留最近几段已完成矿道，默认且最少为 1 |
| Progression → Recycle Hidden Time | 开启回收时，旧入口完整位于相机后方的持续时间，默认 0.75 秒，最少 0.5 秒 |

灯光参数是便于调节的无单位亮度，不是坎德拉。修改后重新 Play 生效。近距离光照采用受控衰减，避免头灯贴岩壁时一片白；补光固定在角色胶囊内，不随视线转动而丢失脚下照明。灯光调整只由本生成器应用到玩家，不改变其他普通关卡的默认灯光行为。

`Direct Room Faces` 在 Generation 的高级设置里，正常保持开启。旧绕行规划器仅作为兼容模式保留；其 Tunnel Width / Height、Door Margin、Max Slope、Search Distance 在直连模式下隐藏，不影响当前通道尺寸。

## 单向推进与旧段保留

例如：房间 A → 矿道① → 房间 B → 矿道②。开始时只有①可挖；角色胶囊完整进入 B 并通过确认后，①冻结、②激活。碰到门口不会提前切换，转动镜头也不会触发房间切换。按房间顺序单向推进；已经完成的段不会因为走回去重新启用。

- **Keep Frozen（默认）**：旧段保留挖出来的外形、渲染与碰撞，不参与新段布尔切割，也不占新段预算。此模式不会释放旧网格的内存，且不是物理禁止走回旧区。
- **Seal And Recycle（可选）**：至少保留刚走过的一段；更早的段只有在玩家远离、整个旧入口持续处于相机后方，并确认不会与后续房间/矿道的包围盒相交时，才先生成永久不可挖的基岩封口，再清空旧段的运行时挖掘网格与碰撞。回头会看到封口，不会看到缺口。**这个选项会改变旧入口的外观，不是无痕剔除。**
- 透明/遮罩基岩材质、疑似交叉通道等不能确认安全的情况，保守保留旧段；不会只因暂时看不见就删除。回收可能因此推迟或不发生。
- 初始简易网格与段元数据仍保留，用于 `R` 全关重置；不是销毁所有地形资源。基岩外壳和房间本身不回收。
- HUD 的 Cuts 显示当前活动段成功挖掘次数，Chunks 是内部块数，Largest 是最大单块面数/预算，Reduced 是实际接受的简化累计减面数；Total cuts 是全关累计挖掘次数。Retained triangles 可以超过 30,000，它不是共享预算。抵达终点后没有活动段。
- 等待中的段与已冻结段都会在实际挖掘入口拒绝修改，不只是换一个 HUD 数字。

仍然只编辑房间，不需要摆分段对象或触发盒。默认保留策略适合先验证玩法；需要节省旧地形内存、且接受封口表现时，再开启回收。

## 自动分块与保守简化

本次升级后，原有三条矿道分别为 **4 / 7 / 11 个内部块**。块是推进段内部的网格组件，Outliner 不会多出一堆需要手调的房间。分块参数仅在编辑关卡时重建，不在试玩途中重建，以免抹掉已经挖出的空间。

- 挖掘球碰到几个块，就对这些块使用同一份切割几何。所有结果先验证，再一起提交；其中一块失败或超预算，整次挖掘都不提交，不留下“只挖掉半边”的接缝。
- 只更新实际受影响块的网格和碰撞，远处块保持原样。内部切面不是基岩，切割可以正常穿过；外围不可破坏的基岩仍由原生成器生成。
- 简化约每块 12 次有效切割触发一次，接近单块预算时也会尝试。试玩中计算在后台线程进行，只处理独立网格副本，不访问运行时 Actor；主线程只接受通过检查且版本仍匹配的结果，并更新这一块的碰撞。
- 后台计算期间再次挖这块、重置、重新生成或进入下一房间，旧结果会丢弃，不能把新挖掉的岩石“补回来”。每个推进段最多一项后台简化，避免不断堆积任务。
- 锁定分块接缝、原始外表面、明显折角和探测到的薄壁，检查闭合性、有效性及双向表面采样误差；不强制为了达标而减面。默认 0.5 cm 是**每次简化的检查阈值**，不是全程累计误差的严格数学上界，也不保证所有微小薄壁均可识别。
- 编辑器中的直接脚本压力测试使用同步简化，便于确定性验证；试玩使用上述后台路径。后台耗时不等于卡住游戏线程的时长。布尔切割和碰撞提交仍在主线程，所以不能承诺任何情况下完全没有卡顿。
- 分块沿最长坐标轴切成薄片，保留完整横截面，不是无限三维体素地形。最多每段 128 块；无效设置或生成失败时保留上一版有效地形。

默认参数即可试玩。想降低单次网格更新规模，可适当减小 `Chunk Length`；块越多也会增加组件、绘制和内存开销，不建议直接拉到最小。关闭 `Automatic Chunks` 可回退整段网格用于对照测试。

**边界仍存在：**反复在同一个小块内挖出非常复杂的结构，仍可能达到 30,000 面。先等待后台简化完成，或换位置继续挖；不能通过清零统计假装释放几何。默认 Keep Frozen 仍保留旧块的实际几何与碰撞，总内存不会因为分块就固定不变。

## 玩家尺度：不改地图，让空间相对变大

选中关卡里的 `MiningTunnelGenerator`，展开 **Player Scale**。默认 `Player Scale = 0.7`，其他倍率均为 `1`。

停止 Play 后修改，再重新 Play 生效。不要通过人物的 Transform Scale 或相机的 First Person Scale 代替这组设置。

| 参数 | 用法 |
| --- | --- |
| Enabled | 关闭后完全使用原人物蓝图的尺寸、移动与挖掘配置 |
| Player Scale | 统一比例：`0.7` 为原尺寸 70%，`0.5` 为一半，`1` 为原尺寸。推荐先在 `0.5–1` 内体验 |
| Movement Speed Multiplier | 统一缩放后的额外速度倍率；`0.7` 尺度下设约 `1.43`，可接近原世界坐标移动速度 |
| Jump Height Multiplier | 统一缩放后的额外跳跃高度倍率，默认保持相对跳跃高度和跳跃时长 |
| Step Height Multiplier | 统一缩放后的额外跨台阶高度倍率；不改变可行走坡度 |
| Mining Radius Multiplier | 单独微调挖掘球半径，不改变人物碰撞大小 |
| Mining Reach Multiplier | 单独微调挖掘射线距离 |
| Mining Downward Offset Multiplier | 单独微调挖掘中心向下偏移；`0` 取消下偏，`1` 保持原比例 |

实际值 = **人物蓝图原始值 × Player Scale × 对应微调倍率**。视点、两个骨骼模型和碰撞胶囊随人物整体缩放；没有改骨骼或动画资产。

以当前 C++ 挖掘基准为例，`0.7` 时挖掘半径为 `112 cm`、距离为 `280 cm`、向下偏移为 `28 cm`。HUD 会显示实际生效的比例、距离与半径；如果你改过人物蓝图，使用蓝图的原始值计算，而不是强行覆盖为这些数字。

移动速度、加速度、制动、台阶高度和跳跃同步调整。默认跳跃速度和重力都乘统一比例，保持原来的跳跃时长；额外跳高倍率通过调整起跳速度生效。出生时保持原脚底位置，按 `R` 不会恢复成大人物，也不会越重置越小。

房间、整面直连、基岩、分段预算、材质、曝光以及灯光亮度/照射半径均不缩放。保留原照明覆盖是为了避免小尺度下再次看不清。挖掘间隔、球心内嵌比例也不变。修改玩家设置不会触发地形重建；没有生成器的旧原型地图不受影响。一个关卡只应启用一个生成器的 Player Scale，多个来源同时启用时会警告并保留原人物配置。

**玩家缩放本身不是性能优化开关。** 小挖掘球走完同一段矿道可能需要更多次布尔切割；现在用自动分块分摊面数增长，仍受单块预算约束。想避免挖得太慢，可以适当调整 `Mining Radius Multiplier`，不必为了分摊预算手工增加中转房间。

验证脚本：`verify_player_scale_editor.py` 检查编辑参数不改地形并保存；`verify_player_scale.py` 检查尺寸、微调与重复重置；`run_player_scale_suite.py` 串联比例验证、70% 角色实际挖通和完整重置。独立报告为 `Saved/Validation/player_scale*.json`，不会覆盖旧原尺寸的实际通关报告。

上一版玩家比例验证：313 项比例/微调/重置检查通过；70% 角色以真实移动和挖掘完成 160 次切割，约 82 秒到达全部三个后续房间。这里的面数与耗时是自动内部块升级前的历史对照，不作为本次分块版本结果。

此次还修正了生成器遗留的重复岩体：只清理本生成器所属、但已不在当前生成结果中的旧岩体；重建失败时保留旧结果，成功后清理，并在进入游戏时作防御性清理。不会删除房间、手工岩体或其他生成器的产物。`verify_player_scale_geometry.py` 验证这项清理及直连几何回归；`run_player_scale_validation.py` 可在停止 Play 的当前地图中串联完整编辑/游玩验证。

## 失败提示与当前边界

- `NOT APPLIED` 表示新布局没有应用，保留最后一次有效地形。请看状态后调整房间，不要把旧地形误认为新布局已经生成。
- 房间需要有有效间距；重叠、面朝反方向、编号重复等会被拒绝。
- 直连不会避开第三个房间或其他通道，也不保证任意摆放都能步行通过。交叉部分按前段优先分配岩石，避免重叠的两层可挖几何；单向推进仍严格遵循房间顺序，不适合作为任意分支探索图。
- 坡度大于 35° 时给出提示，但仍生成原样直连，不改成绕路。
- 坡度会随你的房间布局变化，以生成器和连接上的实际提示为准。陡坡可以向下挖落，但不代表能够步行返回。
- 运行时使用已生成网格，不重新生成房间布局；`R` 恢复所有段（包括已回收段）、移除封口、清空进度并回到起点。
- **单块预算仍然存在**：自动分块解决长矿道累计，保守简化减少部分冗余；两者不等于局部无限挖，也没有提高单块 30,000 面保护上限。
- 当前针对本地单人；没有加入联网同步或跨游戏启动的进度存档。极小房间、高速穿越时需结合角色速度调小入室确认时间。
