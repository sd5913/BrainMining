# P0 / P1 音频接入（2026-10-16）

这是可试玩的声音设计版本。新增 14 个音频，共 47 个 Pilot 资源；其中 5 个木地板脚步仍为 P2 备用。新增电机、推进气流、引信、警告和领取提示使用项目内可复现合成，投掷、贴附和爆炸碎石复用已保存授权的 CC0 素材，不能当作专门录制的最终音效。

## 玩家操作

- F8 打开音量设置，Esc / F8 /「保存并返回游戏」关闭。其他鼠标菜单打开时先退出该菜单。
- 五条滑杆分别控制总音量、音乐、音效、环境声、语音；修改立即应用，关闭或正常退出时保存。
- 设置保存至 `Saved/Config/BrainMiningAudio.ini`，不改动项目默认配置，不与画质设置混用。
- 「恢复默认音量」恢复 100%、100%、85%、80%、100%。音乐滑杆的 100% 是制作时混音的满量，不是让背景音乐与爆炸一样响。
- 原开发命令 `bm.Audio.*` 仍是 Pilot 调试开关和相对增益；统一控制所有房间请使用 F8。

## 实际接线

| 系统 | 触发与限制 |
| --- | --- |
| 镐子、碎石、脚步、金币 | 保留真实接触 / 地形提交 / 距离触发；下调密集声音，金币限流改为 200ms |
| 背景音乐 | 矿区默认相对增益从 0.16 降为 0.12；离开矿区淡出；保留原 3 秒首尾交叠和署名 |
| 钻机 | 装备启动、低声待机、按住加速、实际成功挖掘时叠加接触循环、收起停止；能量低于 15% 仅在跨越阈值时提醒 |
| 喷气背包 | 按实际推进状态启动与维持，松开或过热停止；过热只在状态进入时提醒；创造飞行悬停也保留推进声；落地沿用落地事件 |
| 炸弹 | 成功生成时投掷声、附着炸弹的空间化引信、首次有效碰撞、实际 Explode 时爆炸；碎石尾声包含在爆炸音频里 |
| 炸弹并发 | 引信最多 4 路、爆炸最多 2 路；旧声音压低，超额停止最旧声；引信随炸弹销毁清理 |
| 宝物领取 | 成功 E 领取时播放一次反馈，200ms 限流并抑制同次钱包金币提示，避免双重奖励声 |
| 统一混音 | 现有 `/Game` SoundWave / SoundCue 纳入四个 SoundClass；总音量乘以分类音量，通过同一个 SoundMix 更新已播放声音 |
| 结尾与字幕 | 环境组件显式指定 Ambience，语音组件与字幕音频显式指定 Voice；Blood / Brain 同时作短音效和环境音时按播放用途分开 |

工具循环在菜单、输入暂停、失去本地控制、组件停用和关卡结束时清理；钻机另受矿区和遭遇阻挡约束。喷气声跟随真实飞行能力，房间仍允许飞行时保持有效。

旧升级控件 `VortexUpgrade` 目前实际显示的是喷气背包，项目没有持续吸附操作。此次实现真实的 E 领取反馈，没有新增吸附玩法。若后续加入持续吸附，需要提供开始 / 持续 / 结束事件，再接入对应循环。

## 复现与检查

1. 关闭编辑器，运行 `Scripts/Build_Safe.ps1`；编译仍受内存保护、单任务限制。
2. 需要重新制作素材时，依次运行 `Scripts/prepare_audio_pilot.py`、`Scripts/prepare_audio_tools.py`。
3. 运行 `Scripts/AudioPilot_Safe.ps1 -Mode Import`。它导入 47 个音频，创建 `/Game/Audio/Mix`，更新现有声音分类，不保存关卡。报告：`Saved/AudioPilotImport.json`、`Saved/AudioRouting.json`。
4. 运行 `Scripts/AudioPilot_Safe.ps1 -Mode Test`。测试真实角色蓝图的音乐区域切换、钻机接触、推进 / 过热、菜单 / 停用清理、资源导入及配置写盘重读。这是无声逻辑测试。
5. 运行 `Scripts/AudioP1_Smoke.ps1 -Mode Capture -Headless`。以有声、无图形渲染模式进入独立矿区，执行开发用 `bm.Audio.Capture`，记录约 24 秒真实引擎主输出至 `Saved/AudioP1Runtime.wav`。序列为背景音乐、钻机待机 / 一次注入的接触事件、停止、推进 / 停止、真实炸弹投掷、领取提示、总音量静音、音乐循环接缝。它是脚本化验证，不是完整人工通关。测试进程临时设置 `au.DisableAppVolume 1`，避免后台窗口失焦导致整个录音静音；不改变正常游戏的失焦静音设置。去掉 `-Headless` 可以启用图形，但需要更多内存。
6. 运行 `Scripts/verify_audio_p1.py`，生成 `Saved/AudioP1Validation.json` 和 16 秒音乐接缝试听 `Saved/AudioMusicSeam.wav`；如录音存在，同时检查录音非静音和削波样本。
7. `Scripts/AudioP1_Smoke.ps1 -Mode SettingsUI` 在轻量 Entry 场景使用实际玩家控制器，模拟 F8 打开面板，生成 `Saved/AudioSettings.png`，2 秒后模拟 F8 关闭并检查暂停 / 移动 / 视角状态恢复；成功标记为 `AUDIO_SETTINGS_PREVIEW_OK`。`-Mode CampaignUI` 则用低画质启动实际主流程。Capture 约 35 秒、SettingsUI 约 10 秒、CampaignUI 约 120 秒游戏帧后自动退出，启动器上限 180 秒。

有声捕获会临时调整测试局的工具状态、飞行、炸弹和混音，并在正常录制完成时恢复原音量；只允许在独立矿区运行，勿在重要测试进度中调用。

## 验收边界

本次结果：完整编辑器目标编译成功；5 项 `BrainMining.AudioPilot` 自动化全部通过，0 失败、0 警告。47 个 WAV 的采样率、数值、峰值和循环边界检查通过。80 个现有及新增声音完成分类，4 个 SoundClass 和 1 个 SoundMix 已保存并加入 Cook。

实际引擎录音为 24.0 秒，峰值 0.1123，削波样本 0；静音段 RMS 为 0，恢复段 RMS 为 0.005335。已检查 F8 面板截图，并验证打开 / 关闭后的输入状态恢复和设置文件写盘重读。未通过桌面工具实际拖动滑杆；界面事件由引擎测试调用，设置值与持久化另由自动化覆盖。

带图形的矿区试玩启动时空闲物理内存降至约 1.1 GB，现有 ResourceGuard 按既定阈值终止了该测试进程；未降低保护阈值。随后关闭渲染完成了有声录制，轻量图形场景完成了面板验证。因此不能把本次结果描述成完整主流程的图形通关验收。

音频峰值、循环接缝连续性、运行时录音和自动化结果各自记录在 Saved 中。波形连续不等于音乐乐句自然；引擎有声录制不等于人工听感认可。正式发布前仍需耳机和扬声器试听持续钻孔、同时推进、爆炸和结尾语音。未执行整包 Cook、全流程人工通关或移动端测试。
