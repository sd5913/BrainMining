# 挖掘收集 V0.2

独立关卡：`/Game/CollectionPrototype/Maps/Lvl_Collection_V02`。

双击工程根目录 `Play_Collection_V02.cmd` 即可启动独立试玩窗口。原来的 V0.1 短挖掘关卡保留；原挖掘 Demo 和默认启动地图保持原样。收集系统的模型面朝向、描边和检视界面修正也供 V0.1 使用。

## 本轮修改

- **更深的发现路线**：默认挖掘深度参数 1100 cm，藏品距入口约 11–14 米。四类仍随机分配到四个区域。需继续开挖并向内移动，无法从门口直接拿到。
- **延伸线索**：管道从外露喷嘴持续穿过土层，深入到马桶房；彩色液滴和羽毛也分段留在深层土里。
- **洞穴内静置**：马桶、电脑在预先生成的封闭空腔内完全露出，保持静止，不再挖出后弹落。鸟巢里也留有一只静止可收集的鸽子；试管架保留暴露阈值和物理掉落。
- **仅外侧描边**：可收集对象写入 CustomDepth，局部后处理只在物体轮廓外约 2 像素画白边。物体内部颜色保持原样；场景深度用于阻止隔墙透视描边。旧的膨胀白色外壳始终关闭，不更改项目全局渲染配置。
- **沉浸检视**：模型展示占画面左侧大部分区域，渲染目标 1536×1024，下方切换藏品。信息区仅保留名字和两行短介绍，不显示线索。支持拖动双轴旋转、滚轮缩放、双击或 F 复位。
- **蚂蚁爬洞**：入口和电脑旁共 18 只蚂蚁，身体沿路径移动、腿部交替摆动，爬进实际挖出的微型洞口；土层仍遮挡内部蚂蚁。
- **鸟群飞出**：挖掘网格连通后，8 只小鸟沿实际可通行路径陆续飞出，带扇翅和轻微起伏；每轮只触发一次。路径检查不通过时不播放，避免直接穿过完整岩壁。重置后可以再次触发。保留一只藏品鸽子。

## 试玩操作

WASD 移动，鼠标观察；按住左键挖掘，E 收集；按住空格上升、松开下落。Tab 开关图鉴，图鉴内 Esc 返回，R 清空本轮收藏并恢复矿区。独立试玩窗口用 Alt+F4 退出。

建议依次体验：左侧教学试管架及描边 → 沿水管深入 → 蚂蚁洞中的静置电脑 → 飞上去挖通鸟巢 → 图鉴逐件旋转查看。

## 调节与边界

停止 Play 后，选择 `V02 collection rules`。

- `Excavation Depth`：650–1800 cm，默认 1100。修改后重新 Play；随深度延长对应岩体和线索。
- `Exposure Threshold`：仅作用于埋藏的试管架，默认 65%；静置洞穴物品无需掉落。
- `Random Seed`：0 每轮随机，正整数复现同一布局。

当前为单机、单轮原型，无跨局保存。蚂蚁和鸟群使用程序化位移和扇翅，属于初版演出；没有骨骼动画、群体 AI 或动态避让玩家。鸟路径按当前挖掘网格计算一次，目标是通过实际打开的通道。

## 隔离与验证入口

只新增 V0.2 地图及专用描边材质，修改收集系统文件。没有修改现有 DiggableRock 布尔算法、角色蓝图、飞行代码和旧矿区地图。

- 构建：`BrainMiningEditor Win64 Development`。
- 运行期验证：`Scripts/verify_collection_v2.py`，报告在 `Saved/Validation/collection_v02_runtime.json`。
- 图像检查使用独立进程中的测试布景；测试直接切割用于准备藏品，不代表人工通关。

本次已通过编译、2 项原生收集测试和 42 项运行期检查。运行期测试调用原有挖掘组件，四类藏品分别经历 8–9 次有效切割后收集，并验证鸟群移动、蚂蚁移动、重置和原挖掘 Demo。测试角色的位置由脚本设置，因此该次数用于确认挖掘链路，实际步行、观察和探索时长仍以试玩为准。原有地图、V0.1 地图、配置及预先存在的项目改动共 16 个基线文件哈希均未改变。

本版完成后先试玩确认挖掘时长、管道指引、外侧白边、检视占比和两段动画，再继续下一版。
